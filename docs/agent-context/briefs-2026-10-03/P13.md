# Task P13: Prime Sets card cuts off the last part cell at a medium window width (errors report item 49)
Worktree: this directory. JS/CSS only. Files you may edit: src/components/PrimeSetCard.jsx, new tests under tests/ui/. No locale changes, no Rust, never `scrollbar-width`/`scrollbar-color`. Read docs/RECURRING_ERRORS_REPORT.md section 49 first (symptom and probable cause) and sections 35 and 37 (the label and the x-count badge decisions that must keep working).

## Problem
Cause (probable): src/components/PrimeSetCard.jsx line ~51: `style={{ gridTemplateColumns: `repeat(${Math.min(set.parts.length, 6)}, 1fr)` }}`. A plain `1fr` column cannot shrink below its content minimum, and each cell is `p-3` plus content (word labels such as "Blueprint", a price badge, a sources link), so a cell keeps a minimum of about 80px and the grid overflows the card.

## Do
1. Make the parts row fit its card at any width: use `repeat(N, minmax(0, 1fr))` so columns can shrink; reduce the cell padding at narrow cell widths (for example `p-3` becoming `p-1.5` when the cell is narrow; use container queries or a width-based class choice computed from the part count, NOT a window media query alone, because the card width depends on the page layout); let long words break (`break-words`, `hyphens-auto` is optional) and keep labels wrapping to two lines (item 35 behavior); keep the price badge, the x-count badge centered above the image (item 37 decision), the label and the sources link inside the cell without overflow; images may scale down (`max-w-full`).
2. If five or six cells would each be narrower than about 64px at the available card width, wrap the row onto two lines instead of squeezing further (for example choose the column count from the part count and a minimum cell width of 64px, using `repeat(auto-fit, minmax(64px, 1fr))` or an equivalent that still keeps one row when there is room). Do not change the look at wide widths (one row, equal columns).
3. Tests (SSR/source-level, see tests/ui/prime-set-card.test.mjs and its entry file from the earlier job, same esbuild bundling approach that stubs `?worker|url|raw` imports): render a 6-part and a 5-part set and assert the parts grid style no longer uses a bare `1fr` track (uses `minmax(0, 1fr)` or auto-fit with a minimum), the cells carry the shrink-safe classes, and the badge/label markup from items 35 and 37 is unchanged.
