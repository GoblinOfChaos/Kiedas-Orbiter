# Task P21: Farming Targets: owned targets must stay farmable, and the Target Inspector must always list the full requirements (errors report item 60)

"#60 yes, because you could be searching for things you want that you already have and need more of, or farming for platinum items." So a farming target means "I want N MORE of this", not "tell me what I am missing". An owned target must still be farmable, and the Target Inspector must never be empty for it.

## Current behaviour (verified)
`src/lib/farmingTargets/ledger.js`: `buildLedger` computes `stillNeeded = max(0, required - ownedCount)`; `requirements.js`: owned stock is consumed BEFORE a craftable item's recipe is expanded ("owned stock before their recipe is expanded; raw leaves remain unshortened"), so a target the player owns (quantity 1, owned 1) has `stillNeeded 0` and its recipe is never expanded: no ledger rows, no farm-next ranking, an empty Target Inspector, no build components.

## Do
1. Semantics: the TOP-LEVEL target item's own stock is not subtracted by default: a target with quantity N means N more are wanted, so its recipe is always expanded for N crafts (components and raw resources below it still consume owned stock as today: if the player owns the parts, they are not farmed again). Add a per-target boolean option `countOwned` (default false) stored with the target (see state.js/store.js for how targets persist; migrate old stored targets without the field to the default; keep stores backwards compatible) that restores the old behaviour for that target (owned copies count toward the quantity). Non-craftable targets (a resource or a mod): with `countOwned` false the required quantity is N farmed on top of what is owned, i.e. stillNeeded = N.
2. Target Inspector (`FarmingTargets.jsx` ~lines 119-121 and `targetRows`): for the selected target always list the full requirement tree (every component and resource with required quantity, owned quantity, still-needed, and an owned/needed mark), including when everything is owned; never an empty panel; show where each still-needed item can be farmed as today. Add the per-target switch ("Count the copies I already own" or similar, translated in all 14 locales) next to the target quantity control.
3. Keep: reservations, priorities, ranking and coverage logic, the Group by planet view (item 47), the vendor tab changes of the other job. Do not change how non-top-level items consume owned stock.
