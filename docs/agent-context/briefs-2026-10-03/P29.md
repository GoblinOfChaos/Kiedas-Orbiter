## Problem (verified)
User screenshot, Foundry, Follie recipe: Follie main blueprint 2/1, Neuroptics 1/1, **Chassis 0/1 with "1 BP"**, Systems 1/1. Real inventory (`~/.local/share/kiedas-orbiter-preview/data/user/inventory.json`, loaded by scripts/lib/real-data-harness.mjs): `MiscItems` has the BUILT `/Lotus/Types/Recipes/WarframeRecipes/FollieChassisComponent` x1; `Recipes` has the Chassis, Neuroptics (Helmet) and Systems blueprints x1 each and the main Follie blueprint x2; `PendingRecipes` has the Helmet (Neuroptics) and Systems builds IN PROGRESS. So correct is: Chassis 1/1 (built) with its blueprint 1, Neuroptics 0/1 (building, blueprint 1), Systems 0/1 (building, blueprint 1).
Cause (read in src/lib/inventoryParser.js ~3781-3822 and ~3945-3950): `ownedItemCounts` is built from raw arrays (Suits, weapons, Recipes, ...) but NOT from MiscItems, where built components live (they go into `resourceCounts`); for a component ingredient the code uses `have = ownedItemCounts[component]` only (the non-component branch sums `resourceCounts + ownedItemCounts`), so a built Chassis reads 0. Then the loop over the processed `all` list sets `ownedItemCounts[key] = 1` for every part flagged `owned` whose key is in neither table: Follie Neuroptics and Systems carry `owned = true` with quantity 0 (set by the in-progress build), so they read 1/1; the Chassis is skipped by that fallback because it is in `resourceCounts`. Verify each claim yourself on the real data before changing anything; do not trust this description blindly.
