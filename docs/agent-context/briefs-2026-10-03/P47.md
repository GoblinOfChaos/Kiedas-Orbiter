# P47 - port the bounty rotation/stage handling into the Rust DE drop-table parser (NO build, NO compile, NO flag flip)

## Why
The app downloads and parses DE's drop page in Rust: `src-tauri/src/de_droptables.rs` `fn parse` (the JS `src/lib/deDropTables/parse.js` is only used by scripts/tests).
Commit 8b9aa0ec changed the JS parser so bounty sections (cetusRewards, solarisRewards, deimosRewards, zarimanRewards, entratiLabRewards, hexRewards) keep
BOTH the outer `Rotation A/B/C` header (-> `rotation`) and the inner stage header such as "Stage 1" / "Final stage" (-> `stage`), and `src/lib/deDropTables/convert.js`
needs both to rebuild the legacy `{ rewards: { A:[{...,stage}], B:[...] } }` shape. Read that diff first: `git show 8b9aa0ec -- src/lib/deDropTables/parse.js`.
The Rust parser has no such handling: its header rows with two cells (`th` + empty `td`, or empty `td` + `th`) are dropped, because `probability("")` is None, so bounty rows
get `rotation: null` and no stage. Real HTML is in docs/agent-context/briefs-2026-10-03/data/droptables.html (look at the `cetusRewards` section) and the already-parsed JS output
docs/agent-context/briefs-2026-10-03/data/DropTables.parsed.json (produced by the OLD JS parser; the corrected JS parser output for the same HTML is what Rust must now match: run
`node scripts/de-drop-tables/fetch.mjs`-style parse via `parseDropTablesHtml(html)` from src/lib/deDropTables/parse.js on that html file to get the target rows).
