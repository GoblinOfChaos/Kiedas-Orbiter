# P48b - fix the redirect stage of scripts/wiki-download/download.mjs (same worktree, NO real network calls, NO build)

Verified against the LIVE API (do not re-verify, the sandbox has no network):
1. `list=allredirects&arnamespace=0&arprop=title|ids&arlimit=N` returns only the TARGET: items look like {"fromid":1547831,"ns":0,"title":"1999"} (title = target page; the redirect's own name is NOT given). So `redirectPair` mapping item.title as the SOURCE is wrong, and the current fallback `resolveRedirectTarget` (one request per redirect) would take thousands of requests. Remove that approach.
2. `generator=allpages&gapfilterredir=redirects&redirects=1` is rejected by the wiki ("Use gapfilterredir=nonredirects instead of redirects when using allpages as a generator").
Required new redirect stage (still one request at a time, same throttle/backoff/UA/state/resume as the rest):
 a. List redirect page titles: `action=query&list=allpages&apnamespace=0&apfilterredir=redirects&aplimit=500` (formatversion=2), follow `continue`; store the list in state so it resumes.
 b. Resolve targets in batches of 50 titles: `action=query&titles=A|B|C...&redirects=1` (formatversion=2) and read `query.redirects` = [{from,to,tofragment?}]. Titles that are not redirects or have no `to` are skipped; record unresolved ones in `redirects.unresolved.json` (do not drop silently). Persist progress after each batch so an interrupted run resumes at the right batch.
 c. Output stays `redirects.json` {"<redirect title>": "<target title>"} (sorted). Include `tofragment` as "Target#Fragment" only if present.
Update/replace the redirect tests (mock responses must use these REAL shapes), keep all other tests green, update README. Also make `--limit N` still produce a redirects.json (limit applies to pages only; cap the redirect stage with `--redirect-limit N` default unlimited so tests/smoke runs can be small).
