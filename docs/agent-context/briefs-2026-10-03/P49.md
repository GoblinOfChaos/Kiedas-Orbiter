# P49 - audit EVERY app item against its wiki page (read-only tool + report; NO app code changes, NO build, NO network)

## Why
The app builds each item's "how to get it" from ~20 files and silently ends up with nothing for some items. Proven example (real data, 2026-10-05): the Intact relics Axi A2, Axi A5, Axi V8, Axi M5, Neo O1 show NO source (`unresearched`) although the wiki lists them as sold by Baro Ki'Teer (`wiki-baro-acquisition.json` even has "Axi A2 Relic"); Axi A8 is a Baro relic on the wiki but missing from the hand-written list in src/lib/baroRelics.js. 60 of 3,173 relic entries have no source at all.

## Task: scripts/wiki-audit/audit.mjs (+ tests in tests/wiki-audit/)
For every item in app-routes.json (skip clearly non-acquirable categories only with a stated reason in the report):
1. MATCH the item to a wiki page: exact title, then redirects.json, then documented name variants (relic "Axi A2 Relic"/"Axi A2 Intact" -> wiki relic page; "X Blueprint" -> "X"; Prime parts -> the "X Prime" page; refinements Exceptional/Flawless/Radiant map to the base relic). Record how each match was made (`matchedBy`) and list every unmatched item with its category - do not drop silently.
2. EXTRACT the wiki's acquisition facts from the matched page as structured rows: sections whose heading is Acquisition/Sources/Source/Location/Drop locations/Where to find (any level), the infobox/template parameters that name vendors/sources, `{{Baro}}`-style or vendor templates you find, and for relic/drop pages the module data (e.g. `IsBaro`/Baro flags in Module:Void/data - find the real field names). Each fact: {kind: vendor|drop|relic|quest|market|craft|event|other, where, detail, evidence: <short wikitext/module excerpt>}. Never invent: if you cannot classify a line, keep kind "other" with the raw text.
3. COMPARE with the app's sources for that item and classify: `app_missing` (wiki has a source, app has none/unresearched), `app_partial` (wiki has a source kind the app lacks, e.g. wiki says Baro, app has no Baro), `app_extra` (app has a source the wiki does not mention), `agree`, `no_wiki_page`, `unclassified` (could not parse). Keep it conservative: only flag `app_partial`/`app_missing` when the wiki evidence is a clear vendor/drop/relic/quest statement.
4. OUTPUT: `audit-report.json` (per item: name, category, matchedBy, wikiFacts, appSources summary, status, evidence) and `audit-summary.md`: counts by status and category, the top 50 most common gap patterns, and the full lists of `app_missing` items by category (names only) plus 3 detailed examples per pattern.
