# P53 - route-conflict report for NON-cosmetic items (REPORT ONLY: no app/data changes, NO cosmetics, NO build, NO network)

The per-item wiki audit (scripts/wiki-audit) flags `defects.app_conflict_route`: the wiki names an acquisition route and the app names a different, non-overlapping one. With cosmetics excluded (user decision: no cosmetics) there are ~160 such items (mods, weapons, recipes, resources, companions, gear). The audit deliberately does NOT decide who is right. Your job: make the decision EASY for the user by grouping and gathering evidence.
Steps:
1. Regenerate the inputs in YOUR worktree: `PREVIEW_DATA_DIR=$HOME/.local/share/kiedas-orbiter-preview/data OUT=<dir>/app-routes.json nice -n 19 node scripts/wiki-audit/app-routes.mjs`, then `scripts/wiki-audit/audit.mjs` (cosmetics are excluded by default; read its usage). Use the non-cosmetic `app_conflict_route` list (confirm the count).
2. For EVERY item write: name, category, the wiki fact(s) (verbatim sentence + page title + revid from /home/jedwards/kiedas-orbiter/wiki_store/pages.jsonl), the app source row(s) (text, type, and WHICH data file/source label it came from: `source` field, e.g. "DE export Market price", "warframe/weapon acquisition table" override, "Warframe Wiki", "warframe-items"), and the conflict in one plain sentence.
3. EVIDENCE from Digital Extremes' data (AGENTS.md rule 4: DE PublicExport is primary): for each item check the DE exports in ~/.local/share/kiedas-orbiter-preview/data/export/ (ExportRecipes/ExportWeapons/ExportVendors/ExportKeys/ExportRelics..., plus the cached official drop table DropTables.json under export/de/): does DE data support the app's route, the wiki's route, both, or neither (e.g. a market price entry for the item, a vendor manifest offering it, a drop-table row)? State exactly which file/entry.
4. GROUP into patterns (the same app text/source vs the same kind of wiki claim), with counts; for each pattern propose ONE of: `app_wrong_wiki_right` (DE data contradicts the app), `wiki_outdated_app_right` (DE data supports the app and the wiki sentence is historical/event-ended), `both_valid_app_incomplete` (both routes exist; app lacks one), `needs_game_check` (no DE evidence either way) - with the evidence quoted. Never guess: if DE data is silent say so.
5. Output `route-conflicts.md` (summary table of patterns first, then per-pattern sections with every item) and `route-conflicts.json`; save under scripts/wiki-audit/out/ (git-ignored) AND write a short AGENT_REPORT.md with the counts per proposed class and the top 10 items the user would most likely want fixed first (explain why). Examples to cover: Korumm (app Market 180 Platinum vs wiki Narmer Bounties after The New War), Slaytra (app Market vs wiki Kahl's Garrison), Latron Wraith / Strun Wraith (app 'Reward from Invasions' vs wiki events), Lemnas Staff Skin is cosmetic = excluded.
Run with `nice -n 19`; tests (if you add any) with `--test-concurrency=2`. Touch only scripts/wiki-audit/ and tests/wiki-audit/ (if you add a small checker); NO changes under src/, src-tauri/, or data files.
