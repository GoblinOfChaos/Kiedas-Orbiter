# P65 - read-only filter audit (counts only). Step 1 of the approved filter plan. NO code changes to src/, NO build, NO network.

## Scope
Write one new script, `scripts/filter-audit/audit.mjs`, and run it. Nothing else in the repo changes except the report files below.

## Inputs (read only)
- Player inventory: `~/.local/share/kiedas-orbiter-preview/data/user/inventory.json`
- DE export: `~/.local/share/kiedas-orbiter-preview/data/export/`
- Parser and harness: `scripts/lib/real-data-harness.mjs`, `src/lib/inventoryParser.js`, `src/lib/acquisitionModel/`
- Saved wiki pages (the saved folder is at `/home/jedwards/kiedas-orbiter/wiki_store/`, outside this worktree)

## Checks to produce (counts and short name lists only, at most 8 names per bucket)
1. Weapon-type buttons: parse the inventory, and list every weapon item that the Primary / Secondary / Melee buttons do not match, grouped by its category and its `weapon_type` value.
2. Consumed suits and evolution records: compare the 55 consumed-suit paths (raw inventory) and the 25 `EvolutionProgress` records against the weapon and warframe rows the parser builds. Report how many match, how many do not, and the unmatched names.
3. Incarnon flag: for every weapon with `is_incarnon` true, report whether it has an `EvolutionProgress` record. Count the flagged weapons with and without one, grouped by category.
4. Adapters: count the `IncarnonUnlocker` items in the raw inventory (`MiscItems`), listing family names.
5. Relic vault state: for each relic in the relic catalog (`getRelicCatalog`), classify as: vault date in the past, vault date in the future, no vault date, or Baro exception. Report the counts and the visible `vaulted` value the app shows for each class.
6. Prime Sets ownership: list Prime Sets where the finished item is owned but a part is not, and Prime Sets where a part is owned but the finished item is not (counts, 8 names each).
7. Foundry ownership: count recipes where `fullItemOwned` is true because the plain-name item is owned, and where it is true only through the Prime fallback (the lookup at `src/lib/inventoryParser.js` around line 4016). Report the counts.
8. Catalog completeness: for each Inventory tab that lists only owned items, report the count owned and the count in the catalog list for the same category (`arcanes`, `mods`, `consumables`, `peely_pix`, `landing_craft`).
9. No-acquisition list: for every item in the Inventory tabs, check whether the app's acquisition result (`getAcquisitionInfo` as used by the drawers, or the model in `src/lib/acquisitionModel/`) returns any source. Write the items with no source to `docs/agent-context/reports/no-acquisition.md`, grouped by category, with the name and unique name for each. Include relics. Do not invent sources.

## Outputs
- `docs/agent-context/reports/filter-audit.md` (the counts for checks 1 to 8, plain text, under 150 lines)
- `docs/agent-context/reports/filter-audit.json` (the same numbers, machine-readable)
- `docs/agent-context/reports/no-acquisition.md` (check 9)

## Run mode
This run is non-interactive and unattended. Do not ask for confirmation and do not stop after planning. Start immediately. A before-and-after proof copy is NOT required, because this task changes no code. Write the reports even if a check fails, and say which check failed.

- Run only with `timeout 240 nice -n 19 node --max-old-space-size=3000 scripts/filter-audit/audit.mjs 2>&1 | tail -n 60`.

- Use `$TMPDIR` for anything temporary, never `/tmp`.
- Do not change any file under `src/`, `src-tauri/`, `tests/` or the data folders.
- If a check cannot be computed, say so in the report and continue. Do not guess.
