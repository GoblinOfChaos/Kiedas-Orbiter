# P66 - Foundry: remove the Prime fallback from the built-item ownership lookup. NO build, NO network.

## Run mode
Non-interactive and unattended. Do not ask for confirmation and do not stop after planning. Start editing immediately.

## Rule being enforced
Owning a Prime item must never mark the plain (non-Prime) item or its recipe as owned. Each item is owned only by its own name.

## The change
In `src/lib/inventoryParser.js`, the built-item lookup around line 4016 currently reads `nameToItem.get(baseName) ?? nameToItem.get(baseName + ' Prime')`. Remove the `' Prime'` fallback so the lookup uses the exact `baseName` only. Change nothing else in that file. Leave the Prime Sets code (around lines 2660 to 2760) untouched.

## Evidence it is safe
The audit (`docs/agent-context/reports/filter-audit.md`, check 7) found 567 recipes owned by their plain name and 0 owned only through the Prime fallback. So the change should move no items on the real inventory today. Verify this yourself with a count-only check.

## Tests (named files, `timeout 180`)
Create `tests/inventory/foundry-prime-fallback.test.mjs` with:
- A synthetic test: an inventory holding only "Foo Prime" does not mark the recipe for "Foo" as owned.
- A synthetic test: an inventory holding "Foo" marks "Foo" owned.
- A real-data test: the count of recipes owned before and after must be equal on the real inventory, with no counts asserted in the test file itself.

Run: `timeout 180 nice -n 19 node --test --test-concurrency=2 tests/inventory/foundry-prime-fallback.test.mjs 2>&1 | tail -n 60`
