## Rule (decided by the owner)
- A relic is vaulted only when its vault state is confirmed vaulted (a vault date in the past). A relic with no vault date is unknown: it is NOT vaulted.
- Precedence (decided by the owner): the Baro exception wins over any vault date in the export. The export gives Axi A8 a past `vaultedAt` date, but Axi A8 is a Baro relic and is NOT vaulted. It gets no tag. Record this precedence in the code comment and in the report.
- The six Baro-exclusive relics (Axi A2, A5, A8, M5, V8, Neo O1) are NOT vaulted. They are sold only while Baro Ki'Teer is visiting. They have no vault date in the export, so they must be set to not vaulted explicitly, not left as unknown. In `src/lib/relicParser.js`, `getRelicVaultedStatus` (line 93: `if (BARO_RELIC_NAMES.includes(relicKey)) return true;`) must return false for these instead of true. Update the comment there to say they are sold by Baro and not vaulted.
- An item is vaulted when every known relic source it has is a confirmed-vaulted relic, and it has at least one such source. If any source is available or unknown, the item is NOT vaulted.
- A vaulted item (or vaulted relic) shows this text in place of its sources: "This item is currently vaulted, check wiki for details." with a link to its wiki page (the existing `wikiLink` value). The text is a translation key; the English text is given above.
- Unknown must never show this text.
