# Item completeness harness

This report is generated by the section 1 implementation in `scripts/item-completeness.mjs`.
The checker follows `parseInventory()` for the Inventory and Foundry projections and uses
the bundled acquisition records as a file-read shim because `loadAcquisitionData()` calls
Tauri `invoke('read_file_bytes')` and cannot run in plain Node without that shim.

## Checks

- Inventory: canary is in `parseInventory(...).warframes`, with a resolved English name and image.
- Foundry: if DE `ExportRecipes` has the canary as `resultType`, the parser's `craftable` projection
  must contain it and every projected ingredient must have a resolved name and image.
- Acquisition: source rows for the parent and component records must retain a blueprint/part label;
  unlabelled component rewards attributed to the parent fail.
